# 普通高清版旧动画核对（2026-10-22）

## 依据与发现

对照 Git `v2.4.0`、现存旧 `wumi` 资源和当前 `umi` 高清资源；仓库没有 `v2.4.1` 标签，不能将本地工作区称为该标签。

待机、思考、工作、开心、担心、等待的开闭眼帧，以及四种说话口型均仍在。放大镜和埋头搜索仍是完整帧序列。问题不只是资源是否存在：新图的 `approvedWholeFrames` 保护在运行期清零了全部运动参数，使普通状态只剩表情帧切换。

固定开眼帧、6秒每300毫秒取样，修复前 idle/think/edit/wait/listen/success/error/rest 各只有一个画面；同样素材交给旧运动逻辑会产生多个画面。

## 修复范围

- 普通高清版明确启用 `allowWholeFrameMotion`，恢复静态完整图的原整体位移、轻转与状态节拍。
- 普通状态不增加缩放式呼吸。开闭眼沿用同一运动时钟，不因换眼睛重启动作。
- 旧耳、爪、脸部区域坐标不复用到新图；局部变形仍禁用。此项不能写成“所有旧局部动作已恢复”。
- 已烘焙的放大镜、埋头搜索、表情影片保持原帧，不叠加整体或局部运动。
- 新九表情完整图不自动继承普通姿势运动；全动态版仍由它的独立影片控制。旧像素资源与原逻辑不变。

## 验证

`tests/ordinary-simple-motion.mjs` 检查八类状态实际像素变化、暂停、眨眼同一运动时钟、固定缩放，以及放大镜/搜索原帧一致。

`tests/regular-frame-animation.mjs` 额外检查实际生成的 DSH 控制器返回多个整体变换；普通版开闭眼显示比例始终一致，全动态 fallback 不叠普通运动。

这轮只生成本地修复与评审预览。安装、推送和发布仍需各自明确执行。
