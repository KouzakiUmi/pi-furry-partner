呜咪固定待在 Pi 输入框左侧，根据真实会话状态做出反应：思考时用灰爪托下巴，修改文件时双爪打字，运行命令时举着放大镜左右扫描，搜索资料和整理上下文时埋进资料堆、露出尾巴摇晃，输出回答时配合嘴型说话。错误时呈现 xx 眼吃瘪表情，完成后挥爪、轻轻晃脑并 wink，休息时闭眼。角色采用完整设定中的白灰毛男性拟人狼形象，保留灰爪、粉色肉垫、白腕毛、蓝围巾与带星线的灰蓝尖耳帽。

首次使用安装脚本且尚未选择界面模式时，使用 Pi 的 `fullscreen` 模式：输出在独立区域内滚动，输入框、角色和 footer 固定在底部。已有安装更新时保留已选模式；也可以使用 `regular`。扩展布局是 `editor`，风格是 `umi`，名称是“呜咪”，底部信息使用 `compact`。启动时在输入框左侧播放一次约 5 秒的“打盹 → 察觉动静 → 睁眼 → 问好”睡醒过程，随后进入实际状态。角色始终属于输入区，不做从启动页滚动飞到输入框的跨区域动画。重新加载扩展时直接恢复当前会话状态。

本插件用于运行 `pi` 命令的 Pi Coding Agent 交互终端。非交互、JSON、RPC 等调用不显示角色，也不启动终端动画。

## 安装与启动

完整自动化验证环境是 Windows、Pi 1.2.0、Windows PowerShell 5.1 / PowerShell 7；Pi 1.3 另通过输入、拖选、鼠标、Sixel/Kitty 图像传输及实际扩展集成等交互回归。另在 **NixOS 26.05 (Yarara)、Pi 1.3.0、Kitty 0.49.1**（`TERM=xterm-kitty`）完成实机补充验证，角色显示、实时动画、`auto`/`kitty`/`blocks` 切换和日常交互正常。该手动验证不替代 Pi 1.2.0 完整套件；界面中文与 Pi 文档提示精简仍严格匹配 Pi 1.2.0，不能把 1.3 的交互检查视作这两个兼容层已开放。请先安装并配置好 Pi。

从 [Releases](https://github.com/KouzakiUmi/pi-furry-partner/releases/tag/v2.4.0) 下载 ZIP 并解压。关闭 Pi，在解压后的**项目根目录**（有 `install.ps1` 的目录）打开 PowerShell：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
pi
```

脚本兼容 Windows PowerShell 5.1 和 PowerShell 7；执行策略参数只作用于这次启动的进程。安装到当前用户的 `~/.pi/agent/extensions/pi-furry-partner/`，主题放在 `~/.pi/agent/themes/pi-furry-night.json`。这里的 `~` 表示当前用户的个人目录。

首次安装且 `tuiMode` 缺失时，安装脚本使用 `fullscreen`；已有模式值时保留，更新也保留用户的选择。安装后请完整退出并重新启动 Pi，让扩展、输出滚动区和鼠标路由一同加载。`/reload` 只重载扩展，不能替代安装时的渲染模式变更；以后仅更新扩展资源时可使用 `/reload`。想完整观看睡醒过程，也可以使用下方的演示命令。

自定义 agent 目录：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -AgentDir 'D:\PiProfile\agent'
```

安装脚本只设置 Pi `settings.json` 中的四个 UI 字段，保留默认模型、provider、已有 packages 和其他配置：

| 字段 | 安装值 | 作用 |
| --- | --- | --- |
| `theme` | `"pi-furry-night"` | 应用角色配色 |
| `quietStartup` | `"header"` | 保留简短启动标题，隐藏资源清单 |
| `collapseChangelog` | `true` | 折叠启动更新日志 |
| `tuiMode` | 缺失时使用 `"fullscreen"`；已有值保留 | 全屏模式使用独立输出滚动区、固定输入区和 Pi 原生鼠标路由；普通模式保留终端滚动记录 |

扩展由 Pi 的扩展目录自动发现，脚本不再向 `settings.extensions` 或 `settings.packages` 注册第二份。保留这一种加载方式即可。

### 高清显示与终端要求

高清头像可使用 **Kitty Graphics Protocol** 或 **Sixel**；普通字符块模式仍可使用插件和动画。`renderer: "auto"` 优先使用 Pi 检测到的 Kitty 图片能力，在 `WT_SESSION` 且未经过 tmux 的 Windows Terminal 中使用 Sixel，其余环境回退字符块。Windows 推荐 **Windows Terminal 1.22 或更新版本**；PowerShell 是 shell，单独升级 PowerShell 不会让旧终端支持图片协议。

已在 **NixOS 26.05 (Yarara)、Pi 1.3.0、Kitty 0.49.1**（`TERM=xterm-kitty`）实机确认 Kitty PNG 的角色显示与实时动画正常。该结果不代表 tmux、SSH、嵌入式终端或所有字体、DPI、窗口尺寸组合均已验证。

1. 在支持的本地终端启动 Pi；输入 `/mascot` 查看实际选中的 `kitty`、`sixel` 或 `blocks`，再用 `/mascot demo` 检查动画，`/mascot demo off` 退出演示。
2. 使用 `/mascot render auto` 恢复自动选择；可用 `/mascot render kitty` 或 `/mascot render sixel` 强制图片后端。明确选择 `kitty` 但 Pi 未检测到该协议时会安全回退到字符块；命令不能为终端增加协议支持。
3. 若头像不显示、乱码或错位，先在不经过 tmux、SSH 或嵌入式终端的本地会话重试；可用 `/mascot render blocks` 获得可用回退，再排查终端与转发链路。

Kitty 使用 Pi 的原生图片编码与生命周期；插件自行编码 Sixel，无需额外安装 libsixel、chafa 或 ffmpeg。Windows 安装器不会修改 Windows Terminal 配置、安装或升级终端，也不会设置永久环境变量；无需运行所谓“高清开启脚本”。

### 从旧名称迁移

已有 `pi-wink-companion` 脚本安装时，直接运行新版 `install.ps1`。脚本会保存旧扩展、旧主题和安装记录，迁移到 `extensions/pi-furry-partner/` 与 `themes/pi-furry-night.json`，归档旧扩展目录，避免两份同时自动加载。2.x 的 `config.json` 仅精准迁移旧风格 ID，其余字节保留，原有界面模式和首次安装前的恢复基线也继续沿用。迁移后完整退出并重启 Pi；不要同时手动复制旧目录回来。

### Pi 原生包管理器

也可以通过 [Pi 官方包管理器](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/packages.md)安装固定版本：

```sh
pi install git:github.com/KouzakiUmi/pi-furry-partner@v2.4.0
```

该路线加载 `package.json` 声明的扩展和主题，**不运行 `install.ps1`，不迁移旧脚本目录，也不设置上表中的四个 Pi UI 选项**。重启后可在 `/theme` 选择 `pi-furry-night`，在 `/settings` 选择界面模式。此路线的源码与 `config.json` 位于 Pi 管理的 Git 包目录，不在上文的手动扩展目录；用 `/mascot` 命令调整偏好即可。

每次选择一个安装来源。已有脚本安装的用户优先继续脚本路线；改用包管理器前先卸载旧脚本安装，避免双份扩展。原生包管理器安装的包也应通过 Pi 的包管理流程移除，不使用本项目的脚本卸载。

## 中英文切换

```text
/mascot language auto
/mascot language zh-CN
/mascot language en
/mascot language status
```

语言偏好保存到扩展 `config.json` 的 `language` 字段，默认值为 `auto`：检测系统语言，中文环境使用 `zh-CN`，其他语言环境使用 `en`。已有配置缺少该字段时也自动检测，明确保存过的 `en` 或 `zh-CN` 继续保留。`zh` 仍是简体中文的命令别名；用 `/mascot language auto` 恢复跟随系统，`status` 可查看保存偏好与实际语言。检测优先读取语言环境变量，再读取可用的 Windows 界面语言，最后回退到运行时语言环境；启动时检测一次，重新选择 `auto` 可刷新检测。语言切换会立即更新状态短句、气泡、输入框控件、快捷操作和信息面板，不重启当前 agent 状态、不清除输入草稿，也不重新播放启动动画。默认名字和副标题随语言显示为“呜咪 / 你的工作搭档”或“Umi / Your coding companion”；自定义名字和副标题保持原文。

`language` 与三个文本开关分别保存：

| 设置 | 简体中文模式 | English 模式 |
| --- | --- | --- |
| `/mascot locale` | 开启时应用兼容范围内的 Pi 原生中文补丁 | 暂停中文补丁，保留开关偏好 |
| `/mascot prompt` | 开启时精简已确认的 Pi 文档提示为中文 | 开启时精简已确认的 Pi 文档提示为英文 |
| `/mascot persona` | 开启时追加中文 Umi 口吻模板 | 开启时追加英文 Umi 口吻模板 |

提示词与口吻的变化从下一轮请求生效。切换语言不会翻译会话正文、代码、工具输出、模型名、路径、自定义 `SYSTEM.md` 或项目 `AGENTS.md`。切回中文时，`locale` 按原有偏好恢复，不会因为选择过英文而丢失设置。

## 界面与状态反应

头像和简短气泡跟随输入区显示，动态图标与呜咪短句合并在输入框顶边，替换原来的 Working 标题；不再额外占用一行状态。宽度允许时，同一顶边还显示工具、耗时或并行数量等细节。输入框保留 Pi 原生编辑器的发送、换行、补全和快捷键；多行输入会增加输入框高度。终端较窄或较矮时自动收起大头像，保留顶边状态并优先保证编辑空间。当前规则在少于 60 列或 22 行时收起侧边头像；头像尺寸也会随可用高度限制。

角色上方的气泡使用完整的三行圆角边框，上下边框闭合，文字在中间行居中，两侧各有一个 `🐾`。思考时的 `·` 点点也居中显示；空闲时输入框顶边使用 `🐾` 图标。

状态来自 Pi 的实际事件：等待模型、文本输出、工具开始与结束、用户交互、上下文整理以及本轮成功、失败或取消。工具运行中显示当前工具；并行工具会显示数量。标签、气泡和短句使用呜咪的第一人称口语，例如“我托着下巴，把这几步接起来”“我盯着工具的输出，等它回个话”“我把前面聊的拢一拢，把重点挑出来”。原有 13 个状态各有 6 条短句，再加 6 条专门等用户回应的短句，共 84 条，另有 14 条按空闲、工作和等候区分的戳戳回应，以及 3 条输入倾听短句；常规轮换文案在同一有效状态内至少保持 6.5 秒，状态变化时切换对应短句。启动、打盹与惊醒提示按各自动作阶段变化。中英文文案都保存在本地，切换语言不额外调用模型。

等待文案按实际事件区分：提问工具或用户交互正在等你答复时，使用 `waiting_user` 文案，例如“我等你拿主意呀，慢慢想就好”；等系统或工具回音时使用 `waiting` 文案，例如“我这里还没收到回应，再等等看”。这只是同一等待状态中的两组表达，不增加新的演示状态。本轮结束只表示这一轮收尾；错误文案会承认这一步没走通，保留对原因与下一步的判断。

呜咪说话使用 `w`、`—`、`o`、`O` 四种嘴型：闭嘴是小 w，小开口为平口，中开口为小 o，大开口为大 O，开口自然放大，适度点出单颗小虎牙。张嘴时不强留 w 型上沿。仅实际文本输出时持续说话；思考、工具调用、输出结束或暂时没有新文本时恢复闭嘴，不把“正在思考”伪装成持续说话。

多数姿态切换带约 200ms 的短过渡，持续的轻呼吸、微晃与偶发耳抖让角色更有生气，并配合眨眼与微动。思考和工作时的眨眼保留原爪姿势。修改文件时使用连续打字动作，运行命令时则举着放大镜平顺地左右查看输出。

放大镜动画使用 MiniMax-H3 从已确认的角色原画生成连续动作，再离线去除背景、抽取完整画帧。头部和握爪跟着镜片左右查看，镜片经过眼睛时能看到眼瞳放大，斗篷随身体轻摆并保留清楚的外轮廓。运行时只按顺序播放，不对镜框局部拉伸，也不在相邻扫描帧之间叠化。插画版与像素版使用相同节奏。旧六帧素材包仍按自己的序列播放，旧两帧素材包保留静态与眨眼回退。

正式放大镜循环包含 64 张视频动作帧和 1 张仅修改眼区的闭眼帧，按 66 个播放步骤组成 6.58 秒的一圈。开头的 420ms 观察停顿拆成睁眼 200ms、闭眼 80ms、睁眼 140ms；其他动作帧至少停留 80ms。背景在离线阶段由绿色信号生成独立灰度遮罩，反相作为 Alpha，再恢复前景颜色。640px 母版和视频保留柔和的透明边缘；240px 终端版的外沿按配套黑色背景近似抗锯齿，80px 像素版保留硬像素轮廓。制作流程见[贡献指南](../CONTRIBUTING.md#角色视频与透明边缘)。

收到修改或运行工具事件时，进入对应姿态并至少保持约 1.2 秒，包含约 200ms 的入场过渡，完整姿态可看见约 1 秒。回到思考时另有约 240ms 缓冲，避免短工具调用导致头像来回闪；即使工具在两次绘制之间快速完成，也会保留这次工作反应。这些措施只作用于角色，真实状态和顶边文案会立即更新。实际运行与预览共用 `lib/motion.mjs` 的动画逻辑；关闭表情时停止循环微动，静态姿态继续更新，主动戳戳仍有短暂反应。

成功挥爪时的 wink 与眨眼已按对应眼区的宽高比例校正，让闭眼线的位置、长度和幅度与原眼睛协调。

等待用户回应时，呜咪会轻轻歪头、带着淡蓝漫画问号眨眼等候；等待超过 10 秒后闭眼打盹。再次收到回应或开始工作时，会先出现约 650ms 的惊醒反应，随后继续真实工作状态。只有姿态受这段反应影响，工具执行和回答不会被延迟。

搜索和整理共用“埋进资料堆”的 MiniMax-H3 连续动作，共 72 幅完整画面、72 个播放步骤，每圈 6.58 秒：脑袋往纸堆里轻拱，尾巴、身体、斗篷和散纸一起衔接。甩尾的波浪与各部位的时间差已经包含在完整动作帧中，运行时不再分别拉动尾巴、头部或纸页，避免连接处被局部形变撕开。尾尖到根部保持深灰、浅灰、白色，尾根与臀部的白毛相连。露出耳朵的其他常规姿势仍有短促耳抖，打瞌睡时保持安静。

默认的紧凑 footer 显示模型与 provider、思考等级、上下文使用比例和窗口大小，以及工作目录、Git 分支、输入/输出 token；缓存和费用只在 Pi 实际提供对应信息且宽度允许时显示。上下文未知时显示未知值。其他扩展的状态仍可显示。`/mascot info native` 可以切回 Pi 原生底部信息；这个设置只影响输入框布局。

如果已有其他扩展接管输入框，本插件会保留该编辑器并提示。此时可以切到 `header` 布局使用启动标题头像。

提交消息后，输入框顶边会显示“准备请求”“等首个输出”或“收到思考、等正文”，并带上已等待的秒数。进入等首输出后，10 秒仍没有回音会明确提示模型还没开口，15 秒起使用提醒色。关闭循环表情时，等待提示仍每秒更新。显示基于本机实际收到的会话事件；工具开始或收到可显示内容后，回到相应工作状态。

表情开启且输入内容实际变化时，空闲或等用户回答的呜咪会抬起灰爪放在耳边，轻轻侧身、点头倾听；停止输入约 1.8 秒后恢复原状态。光标移动本身不触发，真实工具工作时不抢占动作，戳戳回应优先。发送后转入请求准备与响应等待状态。

气泡与头像分别计算宽度：普通尺寸的头像保持 16 × 8 格不放大。终端为 80–119 列时气泡扩为 20 列，头像居中缩进 2 列，输入框比原先右移 4 列；120 列以上气泡可扩为 24 列。60–79 列时收回紧凑布局，较窄或较矮时仍按规则收起头像。英文在两侧爪子与文字之间各预留 2 格，超长文字按真实终端宽度截断。

## 鼠标控件与界面模式

输入框底边跟随 Pi 当前的实际界面模式显示：`fullscreen` 使用可点击的按钮，`regular` 使用快捷键文字提示。每次绘制都会读取当前模式，因此在 `/settings` 切换模式后，底边也会即时更新，无需 `/reload`。宽度不足时按完整项目取舍，保留下来的提示不会把快捷键或功能名截断；未显示的快捷键仍可使用。关闭 `optimizeEditor` 或多行输入需要显示原生隐藏行提示时，底边保留 Pi 原生信息。

`fullscreen` 模式下的按钮如下：

| 控件 | 点击行为 |
| --- | --- |
| `[发送]` | 按 Pi 原生发送逻辑提交当前输入；空输入时禁用 |
| `[换行]` | 在当前光标位置插入换行 |
| `[换装]` | 打开四种角色风格的选择器 |
| `[语气开]` / `[语气关]` | 切换 persona，在 Pi 交互终端的下一轮回答生效 |
| `[表情：开]` / `[表情：关]` | 显示当前循环微动状态，点击切换 |
| 右侧 `[模型]` | 打开 Pi 原生模型选择器；工作中暂时禁用 |
| 右侧 `[思考]` | 按 Pi 原生顺序循环切换思考等级，可在 footer 查看当前等级；工作中暂时禁用 |
| 右侧 `[更多]` | 打开快捷操作菜单；工作中仍可查看用量、工具等可用操作 |

在 `fullscreen` 中，点击角色本身会轻轻戳他一下：短暂露出 `>w<` 表情，缩缩身子、轻轻晃动，再用当前语言回你一句随机的小回应。忙碌时轻轻晃一下，用小短句表示还在认真干活；空闲时更放松俏皮，随后恢复正在进行的动作。它不打断 agent，也不改变动画播放设置。控件只响应普通左键点击；拖动选字不作为按钮点击。它们使用 Pi 的原生鼠标路由。

`[表情：开]` / `[表情：关]` 表示当前状态。关闭后只停止循环微动，静态姿态仍随真实 agent 状态更新；主动戳戳仍有短暂反应。使用这个控件或 `/mascot pause` / `/mascot play` 切换，不会停止 Pi 工作。

`regular` 模式的底边显示快捷键提示，供你按键操作。发送、换行、模型选择和思考切换的提示会读取 Pi 当前的按键映射，支持自定义键位；菜单固定使用 `Ctrl+Alt+W`，也可以输入 `/mascot menu`。这些提示是文字，不是可点击按钮，鼠标继续由终端接管。换装、语气与动画也可以通过下方的 `/mascot` 命令调整；两种模式都能用 `/mascot poke` 逗逗呜咪。

要切换模式，输入 `/settings`，找到 **TUI mode**，选择 `regular` 或 `fullscreen`。通过 Pi 自己的设置菜单切换可以即时生效；安装、卸载或手工修改磁盘中的 `tuiMode` 后应重新启动 Pi。`regular` 使用终端原生 scrollback；`fullscreen` 由 Pi 管理输出滚动与固定底部布局。

regular 模式中的居中提问框不会隐藏左下方未被覆盖的头像；只有实际与弹窗相交的图像条带才会避让。会话内切换模式后也继续追踪弹窗。从早期 2.0 构建更新到这次修复时，请完整退出 Pi 再启动一次，以清除旧会话遗留的弹窗挂钩；之后正常切换模式无需重新加载插件。

已有安装更新保留当前界面模式和完整 2.x `config.json`：已经选用 `regular` 的会继续使用它，风格、尺寸、语气等偏好也继续沿用。完整安装或重装按上方安装表管理四个 UI 字段；界面模式仅在缺失时采用 `fullscreen`。

全屏模式也可以正常拖选文本，`/settings` 中的 **Fullscreen copy on select** 控制是否拖选后自动复制（配置字段为 `fullscreenCopyOnSelect`）。需要强制使用 Windows Terminal 自己的原生选区时，可以按住 **Shift** 拖选；并非所有拖选都必须按 Shift。参见 [Windows Terminal 文本选择说明](https://learn.microsoft.com/en-us/windows/terminal/selection)。

2.3.0 处理了选区切片复制图像 OSC 标记导致条带错列的问题；2.3.1 进一步修复隐藏光标 APC-BEL 标记被复制后，输出解析器持续等待结束符，造成头像黑条和后续文字停住的问题。两项分别处理图像锚点与光标标记；原生拖选事件不会被吞掉，草稿、光标与发送行为继续由 Pi 编辑器处理。回归使用真实 Pi 选区及输出协议，并覆盖分片写入，不代表每种终端环境都已完成实机验收。

`layout` 只支持 `editor` 和 `header`。输入框布局的风格支持 `umi`、`umi-pixel`、`pixel`、`illustration`；标题布局只支持 `pixel` 和 `illustration`，两种布局分别保存风格。`umi-pixel` 保留角色版的五官、服装和各个动作，以 80 × 80 共享色板显示；对嘴线等细笔画做局部采样保护，轻微整理线条颜色，避免细线在缩小后消失。`pixel` 和 `illustration` 继续保留旧造型，便于比较。

例如，切回旧版的插画启动标题：

```text
/mascot layout header
/mascot style illustration
```

回到完整设定的输入框呜咪：

```text
/mascot layout editor
/mascot style umi
```

尺寸也按布局分别保存：输入框使用 `dockSize`，标题使用 `size`。标题滚出可见区域时会暂停整个标题的更新，保护终端滚动记录；切换到输入框布局可让角色持续待在输入区。

`/mascot demo` 或 `/mascot demo all` 使用独立的 70.9 秒时间轴循环展示全部动作，包括输入倾听和戳戳回应。运行阶段停留 7.4 秒，能看完 6.58 秒的放大镜一圈；搜索和整理各停留 7.2 秒，等待阶段停留 12.5 秒，超过十秒后打盹，接着展示惊醒。演示不执行工具、不请求或切换模型，不改配置、输入草稿及真实工具状态；`/mascot demo off` 或新的真实 agent 任务会退出演示。若动画已经暂停，可以先执行 `/mascot play`；完整多姿态演示用于 `editor` 布局。

单状态演示继续接受真实输入倾听和主动戳戳，完整巡演则按自己的时间轴展示这些动作，避免外部短事件打乱顺序。

单独看某个动作时，继续使用 `/mascot demo <状态>`：`idle`、`waking`、`thinking`、`speaking`、`reading`、`editing`、`running`、`searching`、`waiting`、`success`、`error`、`cancelled`、`compacting`。

`off` 不会改变 Pi 当前主题，也不关闭原生界面中文、精简提示词或角色语气；这些功能分别使用自己的开关。配色由 `/theme` 管理，也可在卸载时按恢复规则还原。

## 原生界面中文与文档提示精简

这两项功能分别默认开启，与角色显示、`language` 和 `persona` 语气开关独立。中文模式下，`locale` 只处理界面文字；英文模式暂停中文补丁并保留其开关偏好。`prompt` 只精简下一轮请求中已确认的 Pi 原生文档提示章节，按实际语言使用精简中文或精简英文；身份说明、工具清单和规则继续由 Pi 原生流程构建。可以单独开启其中任何一项，无需启用呜咪语气，也不改变模型、工具权限或现有任务要求。

原生界面中文使用 **Pi 1.2.0 兼容层**，覆盖已识别的原生组件中的固定标题、设置标签、说明和操作提示，包括设置、思考等级、模型、会话、对话树、主题、登录，以及部分选择框、输入框和编辑框提示；另外翻译 24 个内置斜杠命令的补全说明。命令名、参数提示、补全值和实际执行逻辑保持原样。补全翻译同时核对内置命令名、原始英文说明和命令输入位置，因此同名文件、技能及说明不同的第三方命令不会被套用翻译。

`/settings` 主列表支持搜索中文名称和说明，例如“界面模式”或“原生滚动记录”；英文 `TUI`、`mode` 继续使用原生匹配顺序。输入文字和筛选后的设置项保持原样，选中后仍保存 Pi 原始值。模型、会话、主题及独立思考选择器的搜索沿用 Pi 原生规则。

这是部分界面覆盖。模型与 provider 名称、主题名、会话名、用户输入、路径、URL、认证码、正文和工具输出保留原文；动态认证说明、服务商错误、会话状态错误及未识别的第三方界面也不翻译。会话与对话树的列表正文保持原样，扩展弹窗的动态标题和选项保留原文，只处理已知的固定提示。`regular`、`fullscreen`、布尔值及思考等级等内部保存值不变。兼容层不改 Pi 安装文件；其他版本（包括未来补丁版本）或未匹配的文字会保留原文。`/mascot locale on` 或 `off` 在下一次绘制或打开原生菜单时生效，不需要重新发送当前请求。

文档提示精简当前按 Pi **1.2.0** 的原生默认结构核对，只替换精确识别的文档提示 `docs` 章节；文档与示例路径、完整阅读和交叉引用要求保留。身份前言、工具清单和规则保持原生，后续扩展新增的工具、片段与指南仍可动态参与构建。自定义 `SYSTEM.md`、显式强制系统提示词、自定义文档章节、项目 `AGENTS.md`、技能及其它动态上下文保持原样。遇到未知版本或结构时跳过，不进行整段猜译，也不强制返回整串系统提示词。表达更短不保证不同模型中的 token 数按固定比例减少。

`/mascot prompt on` 或 `off` 从 Pi 交互终端的下一轮请求生效，不重写历史。精简内容由 `lib/native-prompt.mjs` 按已确认的文档章节结构生成，关闭后撤掉该章节替换，与角色口吻分开控制。仓库保留的 `prompts/pi-system-zh.md`、`prompts/pi-system-en.md` 及完整提示词格式化纯函数用于离线开发，不会在运行时整段覆盖 Pi 的系统提示词。界面中文和文档提示精简均不额外请求翻译模型；卸载扩展后，后续启动使用 Pi 原生界面与提示词行为。

## 可选的呜咪语气

交付包的角色口吻默认关闭，与外观独立。执行 `/mascot persona on` 后，Pi 交互终端的下一轮回答会采用虚构的 14 岁 Kemono 狼少年呜咪形象：温柔可爱、活泼、带一点俏皮，关键任务时认真稳重。`/mascot persona off` 停止在后续请求中添加该模板，`/mascot persona status` 查看当前开关。切换只影响下一轮请求，不重写已经发送的历史消息。`/mascot off` 控制界面角色；语气需要通过 `persona off` 单独关闭。

角色模板以独立的 `umi_persona` 章节参与构建，保留后续扩展的动态内容。普通技术解释、进度、排错和交付也会自然带上呜咪的口语气息，适当穿插“唔”“呜呀”“嗯嗯”“诶嘿”“嗷呜”等语气词；不机械重复，也不把狼少年写成猫咪。模板只调整回答的语气和表达方式，不改变工具权限、任务要求或工作逻辑。代码、命令、JSON 等结构化内容保持有效，技术准确性和必要的清楚表达优先于角色口吻。

可以编辑已安装的模板文件：

```text
~/.pi/agent/extensions/pi-furry-partner/prompts/wumi-persona.md
```

项目根目录中的 `prompts/wumi-persona.md` 是中文模板源码；英文模式使用 `prompts/umi-persona.en.md`。二者共用 `persona` 开关，按当前 `language` 选用。保存后在下一轮使用；需要刷新扩展时执行 `/reload`。重装前的模板修改随整个旧插件目录保存到安装备份；重装会部署发行包中的模板，可从备份取回自定义版本。

## 渲染与配置

`auto` 在 Pi 检测到 Kitty Graphics Protocol 时选择 Kitty PNG，在 Windows Terminal 环境中选择 Sixel，其他环境使用半块字符。Kitty 与 Sixel 可以呈现更细腻的透明插画；半块字符不要求终端图片协议。三种方式都使用本地帧数据，角色外部显示终端自己的背景。Kitty 后端将每个终端行编码为独立透明 PNG，使输入框旁的图片继续参与 Pi 的逐行布局与差分重绘。若图片协议不可用，可执行 `/mascot render blocks`。GIF/APNG 是可复用的导出文件，Pi 运行时不直接播放 GIF。

需要在启动前覆盖渲染方式时，可设置 `PI_FURRY_RENDER=auto`、`kitty`、`sixel` 或 `blocks`。显式 `kitty` 在 Pi 未检测到该协议时安全回退到半块字符。旧的 `PI_WINK_RENDER` 作为兼容别名继续支持；新变量优先。通常使用 `/mascot render <方式>` 即可，不要求修改 shell 启动配置。

已安装目录中的 `config.json` 保存设置。可以使用命令修改，或退出 Pi 后编辑文件并重新启动。2.3 默认字段如下：

```json
{
  "name": "呜咪",
  "subtitle": "你的工作搭档",
  "animation": true,
  "renderer": "auto",
  "style": "umi",
  "headerStyle": "pixel",
  "layout": "editor",
  "dockSize": "auto",
  "info": "compact",
  "persona": false,
  "language": "auto",
  "chineseUI": true,
  "compactPrompt": true,
  "size": "auto",
  "optimizeEditor": true,
  "enabled": true
}
```

从 1.x 升级时，无 `layout` 字段的旧配置会迁移为 `editor` / `umi` / “呜咪” / `compact`，语气 `persona` 保持默认关闭；旧 `style` 保存为 `headerStyle`，`animation`、`renderer`、`size`、`enabled`、自定义字段等原设置保留。已有 `layout` 字段的 2.x 配置仅将旧 `wumi` / `wumi-pixel` 风格值精准迁移为 `umi` / `umi-pixel`，其余文件内容保留；重新安装不会重置用户的 `persona` 或其他选择；2.x 配置缺少 `persona` 时按关闭处理。缺少 `chineseUI` 或 `compactPrompt` 时，运行时分别按 `true` 处理，加载配置不会为了补字段而改写原文件；后续用命令保存设置时会一并写入这些字段。它们属于扩展的 `config.json`，不增加安装脚本管理的 Pi UI 字段。损坏的 JSON 会使迁移在替换旧扩展前停止。

语言字段缺失时按 `auto` 解析，不会仅为补充默认值而改写已有配置。使用 `/mascot language` 保存偏好后，后续启动会沿用该选择；`auto` 会重新检测系统语言，显式的 `en` 或 `zh-CN` 不随系统变化。

## 备份、卸载与恢复

每次安装前，原始设置、旧插件目录（含完整 `config.json`）、同名主题和安装记录都会保存至：

```text
~/.pi/agent/backups/pi-furry-partner-时间-编号/
```

重复安装和 1.x 升级保留首次安装的主题恢复基线。旧版安装记录尚未管理某个启动选项（包括 `tuiMode`）时，首次升级会分别记录它当时的值或缺失状态。

关闭 Pi，在有 `uninstall.ps1` 的项目根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\uninstall.ps1
```

安装时使用自定义 `-AgentDir`，卸载时传入同一个目录。卸载把当前插件和主题移入新的备份目录，保留本地修改；安装前已有同名插件或主题时恢复原文件。脚本会在移动前检查路径范围，防止越出指定 agent 目录。

四个 Pi UI 设置分别恢复：仅当前值仍等于本插件安装值时，恢复其记录中的原值；原字段缺失时移除，原值为 `null` 时恢复 `null`。例如，原来是 `tuiMode: "regular"` 时恢复普通模式，原来缺少字段时移除；如果用户后来已经改回 `regular`，卸载保留这个选择。模型、provider、packages 和后续新增设置继续保留。卸载不会用整份旧 `settings.json` 覆盖当前设置。完成后重新启动 Pi，使恢复后的渲染模式生效。

## 常见问题

### 头像没有显示，或者图片变成乱码

先执行 `/mascot render blocks` 切换到半块字符渲染，再检查终端是否支持 Pi 检测到的 Kitty Graphics Protocol 或 Sixel。`auto` 在 Kitty 环境优先使用 Kitty PNG，在 Windows Terminal 环境优先使用 Sixel；这不保证每个终端版本都已启用图片协议。不要把图片数据复制到命令行执行。

### 下面的操作不能点

在 `regular` 模式中显示的是快捷键提示，由终端处理鼠标。按提示操作，或使用 `Ctrl+Alt+W` / `/mascot menu`。需要可点击控件时，在 `/settings` 切换到 `fullscreen`。若快捷键被终端截获，命令入口仍可使用。

### 头像消失了，输入框也变窄了

少于 60 列或 22 行时会收起大头像；把窗口放大。也可检查 `/mascot` 的 `enabled`、布局和尺寸。提问弹窗覆盖头像时会按实际交叠避让，弹窗结束后恢复。

### 界面仍有英文

中文兼容层只匹配 Pi 1.2.0 已知的固定界面文案。模型名、主题名、会话正文、路径、服务商信息和第三方插件动态内容本来就保留原文。先用 `/mascot locale status` 查看开关，再核对 Pi 版本。

### 关闭头像后仍是可爱口吻

外观和口吻分别控制。执行 `/mascot persona off` 关闭下一轮的角色模板；`/mascot prompt off` 关闭 Pi 文档提示精简。已发送的历史消息不会重写。

### 更新以后出现两个角色或重复控件

检查是否同时使用了脚本安装、`pi install` 包来源或显式配置的旧入口。只保留一种来源。旧名脚本用户使用新版安装脚本迁移，避免把旧目录重新复制进自动发现路径。

### 其它扩展也自定义了输入框

本插件会保留已经接管输入框的编辑器并提示。可先用 `/mascot layout header` 使用启动标题布局，或调整扩展组合；不要通过强行覆盖另一个编辑器来恢复鼠标功能。

## 素材与验证范围

原始像素素材由本地代码去背景和生成动作。精致插画以及呜咪姿态原稿使用内置图片生成工具，参考用户提供的原图与完整设定；后续裁剪、鼻尖对齐、透明度处理、嘴型、眨眼和帧数据生成均由交付代码完成。`umi-pixel` 从角色姿态派生 80 × 80 像素版本，参考最初像素原图的清楚线条，对嘴部等细笔画做局部保线与轻微色彩整理，保持角色原有比例和形状。搜索姿态的尾巴毛色从尖端到根部固定为“深灰 → 浅灰 → 白色”，阴影不作为额外毛色分段。原始用户图片保持原样。角色渲染、动作演示、只读信息面板和本地素材脚本不调用模型 API，也不需要额外 API Key；Pi 的正常对话及原生会话摘要仍沿用它已有的模型配置。

主要素材位于 `assets/poses/`、`assets/reactions/` 和 `assets/illustration/`；可复现脚本在 `scripts/`。`assets/poses/metadata.json` 记录六姿态的对齐变换及眼、嘴、爪坐标。

快捷入口的模型、思考、会话分组参考了 [tomsej/pi-ext 的 Leader Key README](https://github.com/tomsej/pi-ext#readme)，状态信息与工具详情的按需查看思路参考了 [narumiruna/pi-extensions README](https://github.com/narumiruna/pi-extensions#readme)。这里只参考交互设计，没有复制这两个项目的扩展源码；实际操作由本插件对接 Pi 原生能力。

`editor-preview.gif` 和 `editor-preview.png` 是明确标注的离线效果预览，角色像素由生产环境同款 `activity`、输入区姿态选择和 `motion` 代码导出，再与示例输入区组合；它们不是实际终端截图，图片中的按钮仅展示外观。主 GIF 包含睡醒、思考与工作等状态；`waiting-preview.gif` 单独展示歪头等待、十秒后打盹和再次惊醒，压缩的空等时间会在图中注明。`tail-wave-preview.gif` 并排展示插画版与像素版的完整搜索动作，`tail-wave-contact.png` 提供相位对照。`style-comparison.png` 对比同一呜咪的插画与像素风。`preview.html` 提供不发送模型请求的本地交互预览。
